# M4 配置化实现计划

## 1. 概要

把当前写死的两个参数交给用户，复用已有设置对话框，不新建窗口：

1. **保留条数**：`Store` 的 `kMaxEntries = 1000` 常量改为可设置成员，设置面板用 `QSpinBox` 配置（100–10000），保存后立即裁剪一次。
2. **全局快捷键**：`X11Hotkey` 由写死 `Ctrl+Alt+V` 改为接受任意 `HotkeySpec`；设置面板用 `QKeySequenceEdit` 捕获键位，改键时先 ungrab 旧键再 grab 新键，失败时恢复旧键并回滚 UI。

不涉及数据库结构变更，无需 schema 迁移；不涉及 Wayland（按 PLAN.md 结论明确不支持）。

## 3. 变更方案

### 3.1 `src/core/Store.h` / `Store.cpp`：可配置保留条数

`Store.h`：

```cpp
class Store
{
public:
    static constexpr int kMinRetention = 100;
    static constexpr int kMaxRetention = 10000;
    static constexpr int kDefaultRetention = 1000;

    void setMaxEntries(int entries);          // 夹取到 [kMinRetention, kMaxRetention]，立即 prune()
    int maxEntries() const { return m_maxEntries; }
    // ... 其余不变

private:
    int m_maxEntries = kDefaultRetention;
    // ... 其余不变
};
```

`Store.cpp`：

- 删除 `kMaxEntries` 常量。
- `prune()` 内 3 处 `kMaxEntries` 改为 `m_maxEntries`。
- 新增实现：

```cpp
void Store::setMaxEntries(int entries)
{
    m_maxEntries = qBound(kMinRetention, entries, kMaxRetention);
    prune();
}
```

说明：`prune()` 内部已有 `count() <= m_maxEntries` 短路，重复调用无副作用；UI 层的范围与 `Store::kMinRetention/kMaxRetention` 共用同一组常量，避免两处写死。

### 3.2 新增 `src/platform/HotkeySpec.h` / `HotkeySpec.cpp`：纯逻辑的快捷键描述

职责：字符串 ↔ `Qt::Key` + `Qt::KeyboardModifiers` ↔ X11 keysym，不依赖 xcb 头，便于单测。

```cpp
// HotkeySpec.h
inline constexpr char kDefaultHotkeySequence[] = "Ctrl+Alt+V";

struct HotkeySpec
{
    int key = 0;                                            // Qt::Key
    Qt::KeyboardModifiers modifiers = Qt::NoModifier;

    static bool parse(const QString &text, HotkeySpec *out, QString *error = nullptr);
    QString toString() const;                               // PortableText，如 "Ctrl+Alt+V"
};

quint32 x11KeysymForQtKey(int qtKey);                       // 0 表示不支持
```

`parse()` 规则（失败时写入中文 `error`）：

1. `QKeySequence::fromString(text, QKeySequence::PortableText)`；`count() != 1` → "只支持单组组合键"。
2. `key == Qt::Key_unknown || key == 0` → "快捷键无效"。
3. 必须包含 `ControlModifier | AltModifier | MetaModifier` 至少一个；仅 Shift → "快捷键需包含 Ctrl / Alt / Super"。
4. `x11KeysymForQtKey(key) == 0` → "该按键不支持作为全局快捷键"。

`x11KeysymForQtKey()` 支持范围（其余返回 0）：

| 类别 | 映射 |
| --- | --- |
| ASCII 可打印 0x20–0x7E | A–Z 转小写（`Qt::Key_V` → 0x76）；数字、标点原值 |
| F1–F12 | 0xFFBE–0xFFC9 |
| 特殊键 | Space 0x20、Return 0xFF0D、Tab 0xFF09、Backspace 0xFF08、Escape 0xFF1B、Home 0xFF50、Left 0xFF51、Up 0xFF52、Right 0xFF53、Down 0xFF54、PageUp 0xFF55、PageDown 0xFF56、End 0xFF57、Insert 0xFF63、Delete 0xFFFF |

`toString()` 用 `QKeySequence(QKeyCombination(modifiers, Qt::Key(key))).toString(QKeySequence::PortableText)`。

### 3.3 `src/platform/X11Hotkey.h` / `X11Hotkey.cpp`：支持运行期换键

`X11Hotkey.h`：

```cpp
#include "platform/HotkeySpec.h"

class X11Hotkey : public QObject, public QAbstractNativeEventFilter
{
public:
    static std::unique_ptr<X11Hotkey> create(QObject *parent = nullptr);  // 仅建连接 + 装事件过滤器
    bool apply(const HotkeySpec &spec, QString *error = nullptr);         // ungrab 旧键 → grab 新键
    bool isActive() const { return m_active; }
    HotkeySpec currentSpec() const { return m_spec; }

signals:
    void activated();

private:
    bool initialize();
    bool findKeycode(quint32 keysym);
    bool grabAll(quint16 baseModifiers);
    void ungrabAll();
    bool restorePreviousGrab();

    xcb_keycode_t m_keycode = 0;
    quint16 m_baseModifiers = 0;
    HotkeySpec m_spec;
    // 保留 m_conn / m_root / m_modifiers / m_active / m_filterInstalled
};
```

`create()`：无 X11 连接 → `nullptr`；否则 `initialize()` 只解析 root 并安装 native filter，**不再立即 grab**。因此 grab 失败时仍能拿到对象供设置面板重试。

`apply()` 流程：

1. `keysym = x11KeysymForQtKey(spec.key)`；为 0 → 写 error 并返回 false。
2. `findKeycode(keysym)`；找不到 → "当前键盘布局中没有该按键"。
3. 记录旧 `m_keycode / m_baseModifiers / m_spec`（供回滚）。
4. `ungrabAll()`。
5. `grabAll(newBase)`：尝试 `base`、`base|LOCK`、`base|NumLock(16)`、`base|LOCK|NumLock` 四种；全部 BadAccess → 用旧值 best-effort 恢复 grab，写 error "快捷键 %1 已被其他程序占用"，返回 false；部分成功 → 视为成功（保持与现有实现一致的容错）。
6. 成功则更新 `m_keycode / m_baseModifiers / m_spec / m_active = true`。

修饰键换算（仅在 `.cpp` 内用 xcb 常量）：Ctrl→`XCB_MOD_MASK_CONTROL`、Alt→`XCB_MOD_MASK_1`、Shift→`XCB_MOD_MASK_SHIFT`、Meta→`XCB_MOD_MASK_4`。

`nativeEventFilter()` 匹配改为：

```cpp
constexpr quint16 kRelevantMask = 0xFF & ~(XCB_MOD_MASK_LOCK | kNumLockMask);
if (key->detail != m_keycode)
    return false;
if ((key->state & kRelevantMask) != (m_baseModifiers & kRelevantMask))
    return false;
emit activated();
return true;
```

即忽略 Lock/NumLock 与鼠标按键位，其余修饰键必须精确匹配；绑定含 Shift 的组合键同样成立。

### 3.4 `src/ui/SettingsDialog.h` / `SettingsDialog.cpp`：两个新设置项

`SettingsDialog.h`：

```cpp
#include <functional>

class QKeySequenceEdit;

class SettingsDialog : public QDialog
{
    Q_OBJECT
public:
    using HotkeyApplier = std::function<bool(const QString &sequence, QString *error)>;

    explicit SettingsDialog(QWidget *parent = nullptr, HotkeyApplier hotkeyApplier = {});
    // ...
private:
    bool applyHotkeySequence(const QString &sequence);   // 校验 + 调 applier；失败弹窗并返回 false
    void restoreHotkeyEdit();

    QSpinBox *m_retentionSpin = nullptr;
    QKeySequenceEdit *m_hotkeyEdit = nullptr;
    QString m_appliedSequence;                           // 最近一次成功应用的序列
    HotkeyApplier m_hotkeyApplier;
};
```

UI（「通用」组改造为 `QFormLayout`）：

| 控件 | 配置 |
| --- | --- |
| 开机自启 | 现有 `QCheckBox`，改为表单一行 |
| 保留条数 | `QSpinBox`，`setRange(Store::kMinRetention, Store::kMaxRetention)`，`setSingleStep(100)`，`setSuffix(" 条")` |
| 全局快捷键 | `QKeySequenceEdit`；下方灰字提示"需包含 Ctrl / Alt / Super，仅支持单组组合键（仅 X11）" |

行为：

- **单组组合键**（Qt 6.4 兼容）：连接 `sequenceChanged`，若 `sequence.count() > 1`，用 `QSignalBlocker` + `setKeySequence(QKeySequence(sequence[0]))` 截断到第一段。不使用 `setMaximumSequenceLength()`。
- **即时校验与回滚**：连接 `editingFinished`，取 `toString(PortableText)`，若与 `m_appliedSequence` 不同则 `applyHotkeySequence()`：
  - 成功：`m_appliedSequence = sequence`（尚未落盘，关闭对话框时保存）。
  - 失败：`QMessageBox::warning` 显示 `error`，`restoreHotkeyEdit()` 把编辑框恢复为 `m_appliedSequence`。满足"注册失败回滚 UI"。
- **关闭时兜底**：`done(int)` 中若编辑框内容仍与 `m_appliedSequence` 不同（例如用户在 1s 完成计时器前关闭），同步再尝试一次；失败则提示、恢复旧值，然后照常 `saveSettings()` 并关闭——**不允许因键位冲突把用户困在对话框里**。
- `loadSettings()`：读 `history/maxEntries`（默认 `Store::kDefaultRetention`）、`hotkey/sequence`（默认 `kDefaultHotkeySequence`），并设置 `m_appliedSequence`。
- `saveSettings()`：写 `history/maxEntries`、`hotkey/sequence`（PortableText），沿用现有 `settings.sync()`。
- `m_hotkeyApplier` 为空（非 X11 构造）时跳过 apply，只做保存；启动时 main 会记录不可用日志。

2. 快捷键改为"先创建、再 apply"：

```cpp
auto applyHotkey = [&](const QString &sequence, QString *error) -> bool {
    if (!hotkey) {
        if (error) *error = QStringLiteral("当前环境不支持 X11 全局快捷键");
        return false;
    }
    HotkeySpec spec;
    if (!HotkeySpec::parse(sequence, &spec, error))
        return false;
    return hotkey->apply(spec, error);
};

const QString savedHotkey =
    settings.value(QStringLiteral("hotkey/sequence"),
                   QString::fromLatin1(kDefaultHotkeySequence)).toString();
QString hotkeyError;
if (!applyHotkey(savedHotkey, &hotkeyError))
    qWarning() << "全局快捷键不可用:" << hotkeyError;   // 不静默改写用户配置
if (hotkey)
    QObject::connect(hotkey.get(), &X11Hotkey::activated, &window, &HistoryWindow::togglePanel);
```

## 4. 假设与决策

| 项 | 决策 |
| --- | --- |
| 保留条数范围 | 100–10000，默认 1000（沿用现值）；下限/上限常量放 `Store`，UI 直接引用 |
| 夹取位置 | `Store::setMaxEntries` 内部夹取，UI 只做范围限制，保证 API 被别处调用也安全 |
| 设置键名 | `history/maxEntries`、`hotkey/sequence`，沿用现有 `QSettings`（org/app = `clipman/clipman`），不引入设置对象 |
| 快捷键格式 | `QKeySequence::PortableText`（`Ctrl+Alt+V`），稳定且与平台文案无关 |
| 允许的修饰键 | 至少一个 Ctrl / Alt / Super；Shift 可叠加但不能单独使用 |
| 允许的主键 | ASCII 可打印字符、F1–F12、Space/Return/Tab/Backspace/Esc/方向键/Home/End/PgUp/PgDn/Insert/Delete；其余明确提示不支持 |
| 多段组合键 | 录制时自动截断为第一段；解析层仍拒绝多段（防御） |
| grab 冲突 | `apply()` 先 ungrab 旧键；新键全失败则恢复旧键，UI 回滚并提示；存储值保持原样 |
| 启动时保存的键位被占用 | 只记录警告，不静默切换到默认键（避免用户配置被改写）；用户可在设置中改 |
| Qt 版本兼容 | 不用 `setMaximumSequenceLength()`（Qt 6.5+），用 `sequenceChanged` 截断 |
| 数据库 | 无 schema 变更，无迁移 |
| X11 事件匹配 | 忽略 Lock/NumLock/鼠标位后精确匹配修饰键，避免 Shift 误触发 |
