> 依据 [PLAN.md](file:///home/louis/Documents/VSCodeProjects/QtProjects/Clipboard/PLAN.md) 第 5 节 M2。目标：从"只能存纯文本"扩展到"文本 / 图片 / 文件路径"三类内容，并把单实例、暂停记录、图片清理补成可日常使用的状态。

## 1. 摘要

M2 一次落地 7 项能力：

1. 数据库 schema 升到 **v3**：`entries` 增加 `kind / mime / path / width / height`
2. 平台层按 `TARGETS` 抓取图片（`image/png` 等）与 `text/uri-list`
3. 图片统一转 PNG 落到 `<AppDataLocation>/blobs/<hash>.png`，缩略图落 `<hash>.thumb.png`，库里只存路径
4. 图片解码、缩放、哈希放进 `QtConcurrent` 工作线程，GUI 线程只做 SQLite 写入
5. `text/uri-list` 解析为本地路径列表，面板展示、回填为 `QUrl` 列表
6. D-Bus 单实例：第二次启动不再静默退出，而是唤醒已运行面板（无 session bus 时回退 `QLockFile`）
7. 托盘增加可勾选的「暂停记录」

不改分层结构（`ui/` → `core/` → SQLite，`platform/` → `core/`），不引入新系统依赖（`Qt6::DBus` 已随 Qt 6.8.3 安装）。

## 3. 变更明细

### 3.1 新增 `src/core/ClipboardItem.h` / `ClipboardItem.cpp`

定义跨层共用的数据模型（`ClipboardItem` 由平台层产出，`PreparedItem` 由处理器产出、`Store` 消费）：

```cpp
enum class ClipKind { Text, Image, Files };

QString clipKindToString(ClipKind kind);          // "text"/"image"/"files"
ClipKind clipKindFromString(const QString &value);

struct ClipboardItem
{
    ClipKind kind = ClipKind::Text;
    QString mime;          // Image: 采集到的 image/png 等；其余可空
    QString text;          // Text: 原文；Files: 路径以 '\n' 连接（供 FTS）
    QByteArray data;       // Image: 原始编码字节
    QStringList paths;     // Files: 本地绝对路径（保序）
    int width = 0;         // 平台层不填，由处理器回填
    int height = 0;
};

struct PreparedItem
{
    ClipKind kind = ClipKind::Text;
    QString hash;
    QString mime;
    QString text;
    QString path;          // Image: blobs/<hash>.png
    QString thumbPath;     // Image: blobs/<hash>.thumb.png
    int width = 0;
    int height = 0;
    int byteSize = 0;
    qint64 createdAt = 0;
    bool valid = false;
};

Q_DECLARE_METATYPE(ClipboardItem)
Q_DECLARE_METATYPE(PreparedItem)
```

`kind` 在库里是字符串，读写经 `clipKindToString/FromString`。

### 3.2 新增 `src/core/BlobStore.h` / `BlobStore.cpp`

纯 QtCore（`QDir/QFile`），管 blobs 目录，不碰数据库、不碰 Widgets：

```cpp
class BlobStore
{
public:
    explicit BlobStore(QString dir);

    bool initialize(QString *error = nullptr);        // mkpath
    QString dir() const;
    QString thumbnailPath(const QString &hash) const; // <dir>/<hash>.thumb.png
    QString saveImage(const QString &hash, const QByteArray &png, QString *error = nullptr) const;
    QString saveThumbnail(const QString &hash, const QByteArray &png, QString *error = nullptr) const;
    void remove(const QString &hash) const;           // 删 <hash>.*
    void clear() const;                               // 清空目录内文件
};
```

- 文件命名固定：`<hash>.png`、`<hash>.thumb.png`；`remove()` 用 `QDir::entryList({hash + ".*"}, QDir::Files)` 同时清掉主图与缩略图。
- 写入用 `QSaveFile`（原子替换），失败只返回空串，不抛异常。

### 3.3 新增 `src/core/CaptureService.h` / `CaptureService.cpp`

把"哈希 + 图片解码 + 缩放 + 落盘"移出 GUI 线程：

```cpp
class CaptureService : public QObject
{
    Q_OBJECT
public:
    explicit CaptureService(BlobStore &blobs, QObject *parent = nullptr);
    void submit(const ClipboardItem &item);
signals:
    void ready(const PreparedItem &item);
private:
    BlobStore &m_blobs;
};
```

实现要点：

- `submit()` 记录 `createdAt = QDateTime::currentMSecsSinceEpoch()`（按提交顺序，避免并发完成顺序影响排序），用 `QtConcurrent::run` 在全局线程池处理，`QFutureWatcher<PreparedItem>` 回到 GUI 线程 `emit ready()`。
- 处理规则（`process()`，工作线程内）：
  - **Text**：`trimmed().isEmpty()` 判空丢弃；`hash = SHA-256("text\\0" + utf8)`；`byteSize = utf8.size()`。
  - **Files**：过滤 `QUrl::toLocalFile()` 为空的项；为空则丢弃；`text = paths.join('\\n')`；`hash = SHA-256("files\\0" + text utf8)`。
  - **Image**：`QImage::fromData(item.data)` 失败则丢弃；统一重新编码为 PNG（`QBuffer` + `QImage::save("PNG")`）；`hash = SHA-256("image\\0" + png)`；`m_blobs.saveImage(hash, png)`；缩略图 `image.scaled(128, 128, KeepAspectRatio, SmoothTransformation)` 存为 PNG 到 `saveThumbnail()`；`width/height` 取原图尺寸；`byteSize = png.size()`。
- 任何一步失败 → `valid = false`，`ready` 不发（或发无效项由 main 忽略，实现上直接不发）。
- `QImage` 只在工作线程使用，不触碰 QWidget；这是对 PLAN A.6"core 无 Qt GUI 依赖"的唯一放宽（见第 4 节决策）。

- `open()` 内用 `QFileInfo(dbPath).absolutePath() + "/blobs"` 构造 `BlobStore m_blobs`，`initialize()` 失败只 `qWarning` 并继续（纯文本仍可用），图片写入失败自然被跳过。

**迁移 v3**（`version < 3` 追加，仍在同一事务内）：

```sql
ALTER TABLE entries ADD COLUMN kind TEXT NOT NULL DEFAULT 'text';
ALTER TABLE entries ADD COLUMN mime TEXT;
ALTER TABLE entries ADD COLUMN path TEXT;
ALTER TABLE entries ADD COLUMN width INTEGER;
ALTER TABLE entries ADD COLUMN height INTEGER;
```

- 末尾 `PRAGMA user_version = 3`。旧 v2 行自动成为 `kind='text'`。
- FTS5 外部内容表只依赖 `text_content`，加列不影响索引，**不需要 rebuild**。

**`addItem()`：**

```sql
INSERT INTO entries(hash, kind, mime, text_content, path, width, height, byte_size, created_at)
VALUES(?, ?, ?, ?, ?, ?, ?, ?, ?)
ON CONFLICT(hash) DO UPDATE SET
  created_at = excluded.created_at,
  byte_size  = excluded.byte_size,
  mime       = excluded.mime,
  path       = excluded.path,
  width      = excluded.width,
  height     = excluded.height
```

- 图片的 `text_content` 绑定空字符串（不是 NULL），避免 FTS 触发器处理 NULL 的边界问题；`entries_au` 触发器会照常同步。
- 插入后调用 `prune()`。

**清理时必须同步删 blob：**

- `prune()`：先查超出 `kMaxEntries` 的 `(id, hash, kind)`，对 `kind='image'` 调 `m_blobs.remove(hash)`，再执行原有 DELETE。
- `removeEntry(id)`：先查该行 `hash/kind`，删行后若是图片则 `m_blobs.remove(hash)`。
- `clearAll()`：`m_blobs.clear()` 后 `DELETE FROM entries`（触发器清 FTS）。
- 为避免重复代码，加私有辅助 `bool pruneOverflowBlobs()` 或在 `prune()` 内联即可；保持简单。

**查询：** `recent()` / `search()` 的 SELECT 增加新列并按列序填充 `Entry`：

```sql
SELECT id, hash, kind, mime, text_content, path, width, height, created_at ...
```

### 3.6 `src/platform/XcbClipboardWatcher.h` / `.cpp`

**新增 atom 与成员：**

```cpp
xcb_atom_t m_uriListAtom, m_pngAtom, m_jpegAtom, m_bmpAtom, m_tiffAtom;
QString m_targetMime;          // 当前请求 target 对应的 mime
bool m_suppressArmed = false;
QTimer *m_suppressTimer;       // 复用/新增单次定时器
```

**TARGETS 选择优先级（对齐验收"截图 → 缩略图 → 粘到 GIMP"）：**

1. 图片：`image/png` → `image/jpeg` → `image/bmp` → `image/tiff`
2. `text/uri-list`
3. 文本：`UTF8_STRING` → `text/plain;charset=utf-8` → `text/plain`

> 图片优先于 uri-list：Flameshot 等截图工具会同时提供"图片 + 临时文件路径"，只有图片优先才能满足回填到 GIMP 的验收。

**`requestText()` → `requestTarget(target, mime)`**，记录 `m_targetMime`，其余逻辑（INCR、超时、`SelectionNotify`）不变。

**`finishTransfer()` 按 target 分派：**

- 非 INCR 也要检查 `data.size() > kMaxBytes`（32MB）则丢弃。
- uri-list：按 RFC 2483 拆行（`\r\n`/`\n`），忽略以 `#` 开头的注释行，`QUrl::fromEncoded(line)` → `toLocalFile()` 非空才收集；收集为空则丢弃；否则 `ClipboardItem{kind=Files, paths=..., text=paths.join('\n')}`。
- 图片 target：`ClipboardItem{kind=Image, mime=m_targetMime, data=data}`（不解码，解码交给 `CaptureService`）。
- 文本 target：保持现有 `trimmed` 判空与 `m_lastText` 去重后填 `ClipboardItem{kind=Text, text=...}`。

**抑制逻辑：**

- `suppressNext()`：`m_suppressArmed = true`，`m_suppressTimer->start(1500)`（超时自动清标志）。
- `handleXfixesEvent()`：更新 `m_owner/m_ownerTime` 后，如果 `m_suppressArmed` 且 `QGuiApplication::clipboard()->ownsClipboard()`，清标志并直接 `return`（Qt 自己持有时本就不会抓取，这里只是保证标志被消费而不是留到 1.5s 后误吞用户复制）。
- 保持现有 `m_lastText` 兜底。

### 3.7 `src/platform/ClipboardWatcher.h` / `.cpp`（QClipboard 兜底）

- `suppressNext()`：标志 + 1500ms 定时器；`onChanged()` 开头消费并 `return`。
- `onChanged()` 取 `QMimeData` 后按同一优先级：
  1. `hasImage()`：`qvariant_cast<QImage>(mime->imageData())`，有效则 PNG 编码到 `ClipboardItem::data`，`mime="image/png"`
  2. `hasUrls()`：收集 `toLocalFile()` 非空的路径
  3. `hasText()`：沿用现有 `m_lastText` 去重
- 与 XCB 后端不同，这里的图片字节是 Qt 重新编码的 PNG；与 XCB 不会同时启用，不影响去重。

### 3.8 新增 `src/platform/SingleInstance.h` / `.cpp`

```cpp
class SingleInstance : public QObject
{
    Q_OBJECT
    Q_CLASSINFO("D-Bus Interface", "org.clipman.Clipman")
public:
    explicit SingleInstance(const QString &dataDir, QObject *parent = nullptr);

    bool tryBecomePrimary();   // true = 本进程继续；false = 已有实例
    bool notifyExisting();     // 尽力唤醒已有实例的 show()

signals:
    void showRequested();

public slots:
    void show();               // D-Bus 入口，emit showRequested()
};
```

- `tryBecomePrimary()`：
  - `QDBusConnection::sessionBus().isConnected()` → `registerObject("/Clipman", this, ExportScriptableSlots)` + `registerService("org.clipman.Clipman")`；服务注册成功返回 true，失败（已被占用）返回 false 并回滚对象注册。
  - 无 session bus → 回退 `QLockFile(dataDir + "/clipman.lock")` + `tryLock(0)`（保留 M1 行为，无 D-Bus 的精简环境仍单实例）。
- `notifyExisting()`：同步 `QDBusMessage::createMethodCall("org.clipman.Clipman", "/Clipman", "org.clipman.Clipman", "show")`，`bus.call(msg, QDBus::Block, 1500)`，忽略错误。
- 对象生命周期由 `main` 栈上持有。

## 4. 假设与决策

| 项 | 决策 | 理由 |
| --- | --- | --- |
| 多格式优先级 | 图片 > `text/uri-list` > 文本 | 截图工具常同时提供图片与临时文件路径，必须图片优先才能粘回 GIMP |
| 图片存储格式 | 统一转 PNG，`blobs/<hash>.png` + `<hash>.thumb.png` | 格式单一、扩展名确定，去重哈希稳定 |
| 去重哈希 | `SHA-256(kind + "\\0" + 规范化内容字节)` | 避免三种类型哈希空间互相碰撞；文本沿用 M1 语义 |
| 缩略图 | 持久化到磁盘（128px，PNG），不只在内存缓存 | 面板每次刷新最多 200 条，避免重复解码原图 |
| 图片处理位置 | 新增 `core/CaptureService`，只依赖 QtCore/QtGui（`QImage`），不依赖 Widgets | PLAN A.6 要求 core 无 GUI 依赖，但 QImage 非 Widgets；这是有意的轻微放宽，保证 `core/` 可在无界面测试中使用 |
| 异步边界 | 哈希/解码/缩放/落盘在工作线程；SQLite 只在 GUI 线程 | QSqlDatabase 单线程约束 |
| 回填去重 | `suppressNext()` 改为"忽略下一次捕获"+1.5s 过期 | 图片经 Qt 重新编码后字节不稳定，文本比对不可靠 |
| 单实例 | D-Bus 优先，无 session bus 回退 QLockFile | 兼顾 GNOME 常规环境与精简/无桌面会话场景 |
| 暂停记录 | 仅内存态，重启恢复记录 | M4 设置窗口再谈持久化 |
| INCR 超时 | 维持静默丢弃 | 新增提示需要通知通道，M2 不引入 `org.freedesktop.Notifications` |
| 迁移 | v2 库直接 `ALTER TABLE` 升 v3，不 rebuild FTS | 外部内容表只索引 `text_content`，加列不影响 |
| blobs 清理 | `prune/removeEntry/clearAll` 同步删文件 | 防止库裁剪后磁盘无限增长 |
| 测试 | M2 仍不新增自动化测试，手工验收 | 自动化测试在 M3 用 Catch2/QtTest 统一引入 |

## 6. 验证

**构建（零新增警告）：**

```bash
cmake -S . -B build -DCMAKE_PREFIX_PATH=/home/louis/Qt/6.8.3/gcc_64
cmake --build build -j
```

**手工验收（对齐 PLAN M2 验收）：**

1. 复制文本 → `Ctrl+Alt+V` → 面板出现、搜索、回车回填，行为与 M1 一致。
2. 截图（GNOME 截图 / Flameshot）→ 打开面板：出现 `[图片] W×H` 且带缩略图；回车后到 GIMP 粘贴得到图片。
3. 文件管理器复制若干文件 → 面板显示 `[文件] ...`；回车后在文本编辑器/文件管理器粘贴得到文件列表（`text/uri-list`）。
4. 数据目录（`~/.local/share/clipman/clipman/blobs`）中出现 `<hash>.png` 与 `<hash>.thumb.png`。
5. 删除一条图片记录 → 对应两个 blob 文件消失；托盘「清空历史」→ blobs 目录为空。
6. 用 M1 的 v2 数据库启动 → 迁移到 v3，旧文本记录仍可搜索、复制；`PRAGMA user_version` 为 3。
7. 已运行时再次启动 `./build/clipman` → 进程立即退出，但已有面板被唤起到前台。
8. 托盘勾选「暂停记录」→ 复制文本不入库；取消勾选后再复制 → 正常入库。
9. 复制一张大尺寸截图（如 4K）时观察面板/托盘无卡顿（哈希与缩略图在工作线程）。
10. 快捷键与托盘「显示历史」在 D-Bus 单实例改造后仍正常。

**边界检查：**

- 图片 blob 丢失（手工删除文件）时打开面板不崩溃，回填静默忽略。
- 复制纯空白文本仍不入库。
- INCR 传输大图（> 几十 MB）超过 32MB 上限时丢弃且不影响后续复制。
